# Changelog

Every release of CAIA is recorded here, newest first. Version numbers follow [Semantic Versioning](https://semver.org/): a change to the HTTP API in [docs/API.md](docs/API.md) that can break an existing client is a new major version, a new feature a new minor version, and a fix a new patch version. A change that moves the numbers an analysis gives (a prompt, the calculation, a parameter library) is described in its own line, whatever the version step.

## [1.1.0] - 2026-11-10

Changes that move the numbers an analysis gives: manufacturing is written off over the equipment's lifetime in the forecast mode, size words before a unit are converted, and a stepwise phasing is read as one. Prompts and Karlstad's parameter library changed too, so the reference analyses were run before and after the change (docs/RUNBOOK.md, "Ändra en prompt"). Measured on the four reference analyses, with the calculation step rerun on the same approved steps: the company-car action's net in 2030 went from 126 to 148 tonnes, the public charging points' from 51 to between 24 and 45, the leaf blowers' from 2.6 to 2.2, and the reuse requirement, which buys no equipment, did not move. One whole run read the fleet's three-year renewal as the cars' lifetime and got 15 tonnes again; the reading now says what a lifetime is not, and the same steps give 104 to 117. METOD.md has the details.

- **Manufacturing is written off over the equipment's lifetime in the forecast mode.** Equipment an action makes or buys (vehicles, charging points, machines) used to carry its whole manufacturing in the year it was bought, so an action that replaces petrol cars with electric ones could show a net increase in emissions in its target year while the cars cut emissions for years after. The forecast mode now spreads each year's manufacturing evenly over the equipment's lifetime, and a one-off investment only up to the last year of its benefit. The lifetime is the equipment's, not how long the municipality keeps it: a company car replaced after three years drives on with its next owner. The follow-up mode is unchanged: an intervention already made carries what it has cost. The technical appendix shows ΔE before the write-off beside ΔE, and the method is in METOD.md.
- **Size words are converted.** "500 tusen km" is 500 000 km, and a factor "per 100 km" is converted to per km, as tonnes against kilograms already were. Before, such a driver could come out a thousand times too small or a hundred times too large. A phasing written as "step" or "stepwise" is read as stepwise.
- **The action profile classifies the action as DIN SPEC 91637 does**: level (municipal, regional, national, international), instrument category (regulation, economic instrument, supply and infrastructure, information, own consumption and role model, foundational) and when the effect comes (short, medium, long), in place of the earlier list of action types. Step 2 names each driver's activity shift (annex C of the standard). The classification does not enter the calculation.
- **The report gives each driver's change in its own unit** (km, litres, m²) beside the tonnes, for the target year and the averaging window.
- **A consumption factor above 1 that was read as 1 is marked in both modes**, not only in the forecast mode. In the follow-up mode the reading of the calculation puts the shortest lifetime in the cautious scenario; the prompt said two different things.
- **Karlstad's municipality profile is part of the release**, without five data files from Konsumtionskompassen, whose licence (CC BY-NC-ND 4.0) cannot be combined with the EUPL. Without them the profile's consumption rows use their standard values. NOTICE gives the source and terms of each data file. The tests that read the left-out files are skipped with a reason, and the release keeps its own prompt fingerprints for the profile as shipped.
- Fixes after the review of 1.0.0: target, start and other years outside a sane range are refused instead of computed (a target year of 203 000 kept a request busy for 20 s); the largest analyses, such as twelve drivers to 2045, can be finished; and eight ways the page could show a number or report from one analysis with another are closed. None of these changes a number that could be computed before.
- DOMPurify 3.4.17.
- `docs/METOD.html`, a readable overview of METOD.md generated by `next/tools/metod_html.py`, with a test that fails when the two disagree.
- The batch tools send the system prompt with a cache breakpoint on the direct Anthropic routes. The web app is unchanged.
- Documentation: internal pull-request numbers and names of internal analyses are gone or explained, ARCHITECTURE.md lists all seven tools and today's test count, CONTRIBUTING no longer speaks of pull requests the project does not take, and the README's time for an analysis agrees with the start page.

## [1.0.1] - 2026-11-09

Documentation, comments, two lines the batch tool prints and a citation file. No prompt, calculation, parameter or data file changed, so no analysis gives a different number.

- The README says who brought CAIA about and how the code was written, and a `CITATION.cff` gives the repository GitHub's *Cite this repository* button.
- The README says plainly that model calls go through the installer's own OpenRouter account, may reach providers outside the EU by default, and what it takes to keep them in the EU. What the docs say about Karlstad's installation describes Karlstad's settings.

- The docs no longer contradict each other: Vercel's time limit is 300 s everywhere, and a municipality in production needs a paid plan or its own server; the decision to stay in region iad1 is marked as replaced by arn1 and OpenRouter's EU entry (2026-10-08), and the provider behind the EU entry is named the same way everywhere; the start page does tell the user that text goes to an external provider; the follow-up mode has eighteen method rules, not twelve.
- The README's open items no longer list a missing Content-Security-Policy (the page has one) or a parameter-library row that shifts its columns (it does not), and point to what the comparison with the approved assumptions does not catch, which METOD.md now states as the code does it.
- INSTALL.md clones from the public repository; the deploy-key steps for a private repository are gone.
- The batch tools describe their key list neutrally: a list of Anthropic keys tried in order, OpenRouter last.
- Comments name no individuals, and DECISIONS.md names the client once, in its introduction: a decision gives its date and its reason.
- Operational notes that described one installation's shared login project are written generally.

## [1.0.0] - 2026-11-09

The first public release.

- The web app and the seven-step pipeline: action profile, emission sources, baseline, evidence per driver, calculation, quality review and report. The first four steps are approved or corrected by the user.
- Two analysis modes: forecast (potentialläge) and follow-up of an intervention already made (uppföljningsläge).
- A deterministic calculation in Python (`caia.calc`) with three scenarios, phasing, attribution, territorial and consumption-based emissions, and warnings when the input does not hold together.
- Source marking: every number the calculation rests on carries its origin, checked against the parameter library and data files, and the report shows it under *Talens ursprung*.
- A comparison of the numbers the calculation used with the assumptions the user approved.
- Several actions counted together per emission pot (portfolio), so that the same tonnes are not counted twice.
- The report in three layers on the page, and the HTTP API the page uses ([docs/API.md](docs/API.md)).
- Municipality profiles, with `exempel` as the template for a new municipality.
- Login with Supabase or a shared password, rate limits per user, and the measures from the security review of October 2026.

CAIA was developed at Karlstads kommun from December 2025 and was called Zaid until October 2026. That history is internal and not public; this repository starts a new history.
